# Changelog

## 2026-11-17 — Complete default cloud deployment and automatic identity

- Made the cloud deployment contract complete by default: a single `azd up` bootstraps configuration and Entra API/public-SPA identity, provisions Content Understanding and separate Responses resources/model deployments, configures extraction mappings/custom analyzer and merges the exact SPA callback while preserving existing redirect URIs. The Azure-CLI-backed `scripts/deploy.ps1` uses the same orchestration; local rehearsal remains local.
- Documented `AUTO_CONFIGURE_ENTRA=true`, same-target owned managed-app reuse, service principals and API scope/app roles, scoped SPA preauthorization and only the current operator's demo `manager` assignment. Externally managed apps require automation opt-out and manual callback/role maintenance. No client secrets, directory-role elevation, Microsoft Graph application grants or tenant-wide admin consent are introduced. Directory app-management/app-role-assignment permissions remain prerequisites ([app roles](https://learn.microsoft.com/en-us/entra/identity-platform/howto-add-app-roles-in-apps), [API scope configuration](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-configure-app-expose-web-apis)).
- Documented the preup/bootstrap target guard and persisted inputs before parameter resolution; strict preprovision validation remains non-mutating for directory identity ([azd hooks](https://learn.microsoft.com/en-us/azure/developer/azure-developer-cli/azd-extensibility)). Explicit tenant/subscription intent and verified CLI context are mandatory; automation does not bypass policy, Azure role-assignment authority or quota.
- Documented automatic `CONTENT_UNDERSTANDING_SETUP_PRINCIPAL_ID` / `CONTENT_UNDERSTANDING_SETUP_PRINCIPAL_TYPE` resolution from the actual Azure CLI setup user, rather than relying on azd's reserved principal substitutions. This preserves the correct scoped setup permission when the two CLIs use different users in the approved tenant; explicit overrides are for intentional setup callers, with legacy manual-script fallback retained.
- Recorded configurable `swedencentral`, completion/Responses `gpt-5.2` version `2025-12-11`, embedding `text-embedding-3-large` version `1`, and `GlobalStandard` deployment defaults. Capacity `1` for each is an adjustable low-demo choice, not official capacity guidance or an availability/throughput guarantee. Verified the model choices against [CU supported models](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/service-limits), [model deployment requirements](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/models-deployments), [Foundry availability](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure) and the [retirement schedule](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/model-retirement-schedule); published retirement dates are June 8, 2027 for this completion version and February 9, 2028 for this embedding version. Recheck before deploying.
- Retained the detailed local/manual runbooks, configuration and safety comparisons, citations and historical evidence, while aligning architecture visuals and badges with default-on cloud services and automatic identity. Azure resource deletion does not delete directory applications/service principals: explicit ownership-checked cleanup is required.
- Final local integration `npm test` passed **66/66** on November 17: the previous 47 cases plus 19 default/bootstrap/identity cases. The earlier November 17 **10/10** Edge browser, **3/3** Python documentation and **23/23** tiny-fixture checks were not rerun for this revision; application code is unchanged. Validation remains local/static/mock: no live Azure, Graph, OAuth, provider, representative-corpus quality or production-readiness result is claimed.

## 2026-11-17 — Content Understanding migration

- Replaced the optional Document Intelligence layout path with Azure Content Understanding **custom schema-based field extraction** for varied layouts. The baseline uses stable GA `2025-11-01`, not preview agentic analysis ([analyzers](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/analyzer-reference), [Analyze API](https://learn.microsoft.com/en-us/rest/api/contentunderstanding/content-analyzers/analyze?view=rest-contentunderstanding-2025-11-01)).
- Kept direct local XLSX/CSV/JSON parsing, deterministic calculations, synthetic rehearsal, source-rating separation and human confirmation/manager approval. Cloud candidates require typed field validation, confidence and genuine source grounding; no arbitrary Markdown-number fallback or invented citations.
- Documented the dedicated AIServices S0 extraction account, explicit completion/embedding deployments and Cognitive Services User for runtime/setup. Model names, versions and SKUs are operator-supplied; no retiring model pins are invented ([model deployments](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/models-deployments), [keyless authentication](https://learn.microsoft.com/en-us/azure/ai-services/authentication)).
- Added the separate data-plane setup lifecycle: merge missing model defaults only, reject conflicting mappings, create the custom analyzer, and reject existing schema mismatch. Schema/domain/model changes require a new analyzer ID or separately reviewed migration—not automatic destructive replacement.
- Clarified whole-document model-processing authorization: known detectable restrictions are rejected before extraction; restrictions found only in returned text were already processed by the service. No automatic arbitrary scanned/mixed-document redaction or numeric-correctness guarantee is claimed.
- Refreshed the existing 14 diagram pairs in place, retaining geometry, with official Microsoft Content Understanding product artwork and updated source/identity/configuration boundaries. The artwork comes from the current Microsoft product connector, not another service's renamed icon ([attribution](./docs/assets/icons/README.md)).
- Added an editable review-unit field and missing-unit correction coverage. Evidence details expose actual field confidence, source spans and optional geometry without inventing confidence or source locations; provider labels and offered formats reflect the actual route.
- At this earlier migration checkpoint, verified **47/47 Node tests**, **10/10 Edge browser tests**, **3/3 Python documentation tests** and **23/23 synthetic evaluation checks** (`fixtureOnly=true`) on November 17; documentation checks report zero errors/warnings. Node coverage includes ten new Content Understanding tests and an actual restricted-text PDF preflight; cloud requests remain mocked. Recaptured both existing UI screenshots from the real local synthetic browser rehearsal and visually reviewed both.
- No live service/deployment result or representative-corpus quality result is claimed. The November 17 tiny synthetic evaluation and local/mock results do not validate the live cloud provider.
